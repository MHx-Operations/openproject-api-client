<objective>
Implement PERF-03: rewrite `get_projects_dict` from its current O(n²) shape (each node walks its parent chain, and the outer loop visits every node — total work scales with sum-of-depths, worst case n²) to O(n) using a parent->children index and a top-down traversal that carries each node's prefix-path forward.

Purpose: At ~1000 projects with non-trivial hierarchy depth, the current implementation does on the order of 10^5 redundant scans. The new shape touches each node twice (index build + descent).

Output: Rewritten `get_projects_dict`, two new tests (structural equivalence + 1000-node performance budget), no signature changes, no behavioral changes for any caller of `get_projects_dict` or `get_projects`.
</objective>

  def get_projects_dict(self):
      projects = self.get_paged_collection('projects', page_size=100)
      project_map = {}
      for p in projects:
          project_map[p.id] = p

      for i in project_map:
          p = project_map[i]
          while p.parent_id:
              project_map[i].path_ids.insert(0, p.parent_id)
              project_map[i].path.insert(0, project_map[p.parent_id].name)
              p = project_map[p.parent_id]

          project_map[i].level = len(project_map[i].path_ids) + 1
          project_map[i].fullname = '/'.join(project_map[i].path + [project_map[i].name])

      return project_map

Per-project attributes touched by this method (the output contract):
- p.path_ids  : list[int]  — ordered list of ancestor ids from root to direct parent
- p.path      : list[str]  — ordered list of ancestor names, same ordering as path_ids
- p.level     : int        — depth (root nodes = 1)
- p.fullname  : str        — '/'.join(path + [name])

Project objects come from get_paged_collection('projects', ...). They expose `id`, `name`, `parent_id`, and the four output attributes above (which start as empty list / unset on a freshly decoded resource — see resources module).

  <behavior>
    - Output dict has exactly the same keys (every fetched project's id) as the previous implementation.
    - For each project in the output: `path_ids`, `path`, `level`, `fullname` are populated to values structurally identical to what the previous loop would have produced for the same input list.
    - Root projects (parent_id is None or 0 or otherwise falsy) get `path == []`, `path_ids == []`, `level == 1`, `fullname == name`.
    - Non-root projects get path/path_ids ordered root-first (same ordering convention as the old `insert(0, ...)` pattern).
    - Total work is O(n): no nested loop that walks the parent chain inside an outer per-node loop. Implementation MUST use a parent->children index dict (`children_by_parent` or equivalent) built in one pass over `projects`, then assemble paths by descending from roots, carrying the accumulated (path_ids, path) forward to children.
    - The method signature is unchanged (`def get_projects_dict(self):`).
    - Cycles must not infinitely loop. If a cycle is encountered (defensive guard), break and leave the offending node's path attributes as best-effort empty/partial rather than hanging. (A simple "visited" set during descent is sufficient.) This is a defensive addition — the old code would also have hung on a cycle, but the rewrite should be safer.
  </behavior>
  <action>
    Replace the body of `get_projects_dict` with the following shape (described in prose, not code):

    1. Fetch projects as before: `projects = self.get_paged_collection('projects', page_size=100)`.
    2. Build `project_map = {p.id: p for p in projects}` in one pass.
    3. Build `children_by_parent: dict[int|None, list]` in one pass over `projects`, keyed by `p.parent_id` (which may be None for roots). Use `setdefault(parent_id, []).append(p)`.
    4. Initialize every project's `path_ids` to `[]`, `path` to `[]`, `level` to `1`, `fullname` to `p.name` (these are the root-node defaults).
    5. Iterate over root projects (those whose `parent_id` is falsy OR whose `parent_id` is not in `project_map` — orphan parents are treated as roots, matching the spirit of the original which stopped walking when it couldn't find a parent). Use an iterative stack/queue (not recursion — Python recursion limit + 1000-node fixture). For each root, push (root, [], []) onto the stack; while the stack is non-empty, pop (node, parent_path_ids, parent_path), then for each child in `children_by_parent.get(node.id, [])`:
       - child.path_ids = parent_path_ids + [node.id]
       - child.path     = parent_path + [node.name]
       - child.level    = len(child.path_ids) + 1
       - child.fullname = '/'.join(child.path + [child.name])
       - push (child, child.path_ids, child.path)
    6. Maintain a `visited: set[int]` keyed by `id` of nodes whose subtree has been processed; if a child id is already in `visited`, skip it (cycle guard).
    7. Return `project_map`.

    Do not change `get_projects` (which calls `list(self.get_projects_dict().values())`). Do not introduce a new dependency. Do not change `page_size=100` here — that is the existing in-method literal and is independent of PERF-02.
  </action>
